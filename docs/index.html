Why AccessNexus?Por que AccessNexus?

Row-Level Security is the #1 source of data-access bugs in apps that talk to Supabase directly — verbose SQL, easy to get wrong, and the mistake only shows up at runtime, once a user (or an attacker) has already hit the gap. Recursive RLS (a policy that queries its own table) is a common trap.

Row-Level Security e a fonte nº1 de bugs de acesso a dados em apps que falam direto com o Supabase — SQL verboso, facil de errar, e o erro so aparece em runtime, quando um usuario (ou um atacante) ja bateu na brecha. RLS recursivo (policy que consulta a propria tabela) e uma armadilha comum.

AccessNexus makes your access rules correct by construction and keeps them under version control — not scattered across migrations, drifting from the code.

O AccessNexus torna suas regras de acesso corretas por construcao e as mantem versionadas — nao espalhadas em migrations, fora de sincronia com o codigo.

01 Quick StartInicio Rapido

1. Install & Initialize

1. Instalar e Inicializar

Terminal
# Install
$ npm install accessnexus

# Initialize (auto-detects your framework)
$ npx accessnexus init

Already using Supabase? init adopts your project — it reuses your existing Supabase client and introspects the live database. Point it at a database URL to import tables, RLS policies and functions; without one it imports tables from the PostgREST OpenAPI spec (RLS is not exposed over REST).

Ja usa Supabase? O init adota seu projeto — reusa o cliente Supabase existente e introspecta o banco ao vivo. Aponte para uma URL de banco para importar tabelas, policies RLS e functions; sem ela, importa tabelas via OpenAPI do PostgREST (RLS nao e exposto via REST).

Terminal
# Full import (policies + functions) via a direct DB connection
$ SUPABASE_DB_URL=postgresql://... npx accessnexus init

2. Define your schema

2. Defina seu schema

accessnexus.schema.ts
import { defineSchema, table, policy } from 'accessnexus';

export default defineSchema({
  profiles: table({
    columns: {
      id:    'uuid',
      name:  'text',
      email: { type: 'text', unique: true },
      role:  "enum('admin','user')",
    },
    primaryKey: 'id',
    references: { id: 'auth.users.id' },
    policies: {
      select: policy.isAuthenticated(),
      update: policy.isOwner('id'),
    },
  }),
});

3. Generate & Push

3. Gerar e Aplicar

Terminal
# Generate SQL + SDK
$ npx accessnexus generate

# Apply to your database
$ npx accessnexus push

# Output:
#   Migrations: 1
#   Policies:   1
#   SDK:        types.ts, client.ts
#   Seed:       applied

02 ConfigurationConfiguracao

Create a accessnexus.config.ts at your project root to customize output paths and adapter settings.

Crie um accessnexus.config.ts na raiz do projeto para customizar caminhos e configuracoes do adapter.

accessnexus.config.ts
import { defineConfig } from 'accessnexus';

export default defineConfig({
  schema: './accessnexus.schema.ts',      // schema file path
  seed:   './accessnexus.seed.ts',        // seed file path
  adapter: 'supabase',

  output: {
    dir:        './generated',          // base output dir
    migrations: './supabase/migrations',
    policies:   './generated/policies',
    triggers:   './generated/triggers',
    rpcs:       './generated/rpcs',
    sdk:        './src/lib/accessnexus',
  },

  adapterOptions: {
    dbUrlEnv: 'SUPABASE_DB_URL',      // env var for push/seed
  },

  naming: {
    policyPrefix: 'app',              // RLS policy prefix
  },

  generate: {
    sqlOnly: false,                   // skip SDK generation
    sdkOnly: false,                   // skip SQL generation
  },
});

03 Schema DefinitionDefinicao de Schema

Use table() to define each table with columns, keys, references, policies, triggers, and more.

Use table() para definir cada tabela com colunas, chaves, referencias, policies, triggers, etc.

Full table() API
table({
  // Required: column definitions
  columns: {
    id:         'uuid',                        // shorthand
    email:      { type: 'text', unique: true }, // with constraints
    bio:        'text?',                       // nullable (append ?)
    status:     "enum('active','inactive')",   // inline enum
    tags:       'text[]',                      // array type
    org_id:     'uuid',
    created_at: { type: 'timestamptz', default: 'now()' },
    updated_at: 'timestamptz?',
    deleted_at: 'timestamptz?',
  },

  // Primary key
  primaryKey: 'id',

  // Foreign keys: column -> 'table.column' or 'schema.table.column'
  references: {
    id: 'auth.users.id',       // external schema ref
    org_id: 'organizations.id',  // internal ref
  },

  // RLS policies (see Policies section)
  policies: {
    select: policy.isAuthenticated(),
    insert: policy.isOwner('id'),  // only your own row
    update: policy.isOwner('id'),
    delete: policy.none(),
  },

  // Triggers (see Triggers section)
  triggers: [
    trigger.updatedAt('updated_at'),
    trigger.auditLog({ table: 'audit_log' }),
  ],

  // Soft delete: DELETE becomes UPDATE deleted_at = NOW()
  softDelete: 'deleted_at',

  // Enable RLS (auto-enabled when policies are defined)
  enableRLS: true,
})

05 Database ModeModo Database

If you already have a Supabase project, import your database.types.ts and AccessNexus will infer columns automatically. You only define policies, triggers, and other AccessNexus config.

Se voce ja tem um projeto Supabase, importe seu database.types.ts e o AccessNexus infere as colunas automaticamente. Voce so define policies, triggers e outras configs.

accessnexus.schema.ts (Database Mode)
import type { Database } from './database.types';
import { defineSchema, policy } from 'accessnexus';

// Columns are inferred from Database type - no need to redefine them!
export default defineSchema<Database>({
  profiles: {
    policies: {
      select: policy.isAuthenticated(),
      update: policy.isOwner('id'),
    },
  },
  posts: {
    policies: {
      select: policy.public(),
      insert: policy.isAuthenticated(),
      delete: policy.hasRole('admin'), // global app role (JWT app_metadata.role)
    },
  },
});

06 Policies (RLS)Policies (RLS)

AccessNexus provides 11 composable policy builders that compile to PostgreSQL Row-Level Security.

O AccessNexus oferece 11 builders de policy composiveis que compilam para Row-Level Security do PostgreSQL.

Primitives

Basic rules
policy.public()            // Anyone (no auth required)
policy.isAuthenticated()  // (SELECT auth.uid()) IS NOT NULL
policy.none()              // Block all access
policy.isOwner('user_id') // Row owner: (SELECT auth.uid()) = column
policy.hasRole('admin')   // Global app role: JWT app_metadata.role (not an org role)

Membership & Joins

policy.belongsTo()
// User belongs to same org (via join table)
policy.belongsTo('org_id', {
  table:      'org_members',   // join table
  foreignKey: 'org_id',        // join table FK to tenant
  localKey:   'user_id',       // join table FK to user
  where: { role: ['admin', 'manager'] },  // optional: filter by role
})

policy.matchesField('author_id', 'auth.uid()')  // Two fields must match
policy.custom("status = 'published'")               // Raw SQL escape hatch

Combinators

Composing rules
// OR: any rule must pass
policy.any([
  policy.isOwner('user_id'),
  policy.hasRole('admin'),
])

// AND: all rules must pass
policy.all([
  policy.isAuthenticated(),
  policy.custom("is_public = true"),
])

// Extra condition on the written row: USING (a), WITH CHECK (a AND b)
policy.withCheck(
  policy.isOwner('user_id'),   // USING: which rows can be targeted
  policy.custom("edited = true"), // WITH CHECK: still the owner AND edited
)

07 Permissions (RBAC)Permissoes (RBAC)

For complex apps, define roles and permissions in one place with definePermissions(). Supports multi-tenant scoping via join tables.

Para apps complexos, defina roles e permissoes em um unico lugar com definePermissions(). Suporta multi-tenant via tabelas de juncao.

definePermissions()
const permissions = definePermissions({
  roles: ['admin', 'manager', 'member', 'viewer'],

  // Multi-tenant: how users belong to organizations
  tenant: {
    table:        'org_members',
    userColumn:   'user_id',
    tenantColumn: 'org_id',
    roleColumn:   'role',
  },

  // Permission rules per resource
  resources: {
    projects: {
      ownerColumn:  'created_by',
      tenantColumn: 'org_id',
      read:   { scope: 'tenant' },                              // any org member
      create: { scope: 'tenant', roles: ['admin', 'manager'] }, // + created_by = auth.uid()
      update: { any: ['own', { scope: 'tenant', roles: ['manager'] }] }, // + stays in the org
      delete: { scope: 'tenant', roles: ['admin'] },             // org admins only
    },
  },
});

Using in schema

Uso no schema

Two ways to use permissions
// Option A: generate all policies for a resource
policies: permissions.policiesFor('projects')

// Option B: pick individual rules
policies: {
  select: permissions.can('projects', 'read'),
  insert: permissions.can('projects', 'create'),
}

08 Triggers

AccessNexus generates PL/pgSQL trigger functions and attaches them to your tables. Three presets + a custom escape hatch.

O AccessNexus gera funcoes trigger em PL/pgSQL e as associa as suas tabelas. Tres presets + escape hatch customizado.

All trigger types
// 1. Auto-update timestamp on every UPDATE
trigger.updatedAt('updated_at')

// 2. Soft delete: intercept DELETE, set column = NOW()
trigger.softDelete('deleted_at')
//    or use the table shorthand:
table({ softDelete: 'deleted_at', ... })

// 3. Audit log: log changes to an audit table
trigger.auditLog({
  table: 'audit_log',
  columns: ['name', 'status'],  // optional: log only these columns
})

// 4. Custom trigger with full PL/pgSQL control
trigger.custom({
  name: 'validate_status',
  events: ['before_update'],
  when: 'OLD.status IS DISTINCT FROM NEW.status',
  functionBody: `
    IF OLD.status = 'done' AND NEW.status = 'todo' THEN
      RAISE EXCEPTION 'Cannot reopen a done task';
    END IF;
    RETURN NEW;`,
})

Available events: before_insert, after_insert, before_update, after_update, before_delete, after_delete

Eventos disponiveis: before_insert, after_insert, before_update, after_update, before_delete, after_delete

09 RPCs (PostgreSQL Functions)

Define server-side functions alongside your schema. AccessNexus generates the SQL function and adds it to the typed SDK.

Defina funcoes server-side junto com o schema. O AccessNexus gera a funcao SQL e a adiciona ao SDK tipado.

Three modes of rpc()
export default defineSchema({ /* tables */ }, {
  rpcs: {
    // 1. Database mode: marker only, types from Database
    get_stats: rpc(),

    // 2. Signature only: typed SDK, no SQL generated
    search: rpc({
      args: { query: 'text' },
      returns: 'jsonb',
    }),

    // 3. Full definition: generates SQL + typed SDK
    get_dashboard: rpc({
      args: { p_org_id: 'uuid' },
      returns: 'jsonb',
      security: 'definer',  // or 'invoker' (default)
      language: 'plpgsql',  // or 'sql'
      immutable: false,
      body: `
        RETURN (
          SELECT json_build_object(
            'total', (SELECT count(*) FROM projects WHERE org_id = p_org_id)
          )
        );`,
    }),
  },
});

10 Seed Data

Populate your database with initial data. AccessNexus handles insertion order (FK dependencies) and auto-provisions auth.users entries when needed.

Popule seu banco com dados iniciais. O AccessNexus cuida da ordem de insercao (dependencias FK) e auto-provisiona entradas em auth.users quando necessario.

Idempotent (ON CONFLICT DO UPDATE) Auto auth.users provisioning Auto-runs after push
accessnexus.seed.ts
import { defineSeed } from 'accessnexus';
import schema from './accessnexus.schema';

export default defineSeed(schema, {
  // AccessNexus auto-creates auth.users for these profiles
  profiles: [
    { id: '...uuid...', email: 'admin@acme.com', name: 'Admin' },
    { id: '...uuid...', email: 'user@acme.com',  name: 'User' },
  ],

  organizations: [
    { id: '...uuid...', name: 'Acme Corp', slug: 'acme', owner_id: '...uuid...' },
  ],
});

11 Typed SDKSDK Tipado

AccessNexus generates a fully typed client wrapper around supabase-js. Every table and RPC gets typed methods with autocomplete.

O AccessNexus gera um client wrapper totalmente tipado em cima do supabase-js. Cada tabela e RPC recebe metodos tipados com autocomplete.

generated/sdk/client.ts (auto-generated)
// Auto-generated by AccessNexus
export function createAccessNexusClient(
  supabase: SupabaseClient
) {
  return {
    profiles: {
      findMany, findById,
      create, update, delete
    },
    organizations: { ... },
    rpc: {
      get_dashboard,
      search_tasks,
    },
  };
}
Your app code
import { createAccessNexusClient }
  from './generated/sdk/client';

const db = createAccessNexusClient(supabase);

// Fully typed! Autocomplete works.
const { data } = await db.profiles
  .findMany({ role: 'admin' });

const stats = await db.rpc
  .get_dashboard({ p_org_id: '...' });

12 CLI CommandsComandos CLI

npx accessnexus init

Initialize AccessNexus in a new or existing project. Auto-detects your framework, reuses an existing Supabase client (instead of creating a second one), and introspects your database into a schema. With a database URL it imports tables, RLS policies and functions; with only a project URL + secret key it imports tables from the PostgREST OpenAPI spec.

Inicializa o AccessNexus num projeto novo ou existente. Detecta o framework, reusa um cliente Supabase existente (em vez de criar outro) e introspecta o banco para um schema. Com uma URL de banco importa tabelas, policies RLS e functions; com apenas URL do projeto + secret key importa tabelas via OpenAPI do PostgREST.

SUPABASE_DB_URL ACCESSNEXUS_DB_URL DATABASE_URL
npx accessnexus generate

Generate all SQL files (migrations, policies, triggers, RPCs) and the typed SDK from your schema.

Gera todos os arquivos SQL (migrations, policies, triggers, RPCs) e o SDK tipado a partir do schema.

--sql-only --sdk-only --schema <path> --output <dir> --prefix <name>
npx accessnexus diff

Show changes between generated files and current output (Git-style diff).

Mostra diferencas entre os arquivos gerados e o output atual (diff estilo Git).

npx accessnexus validate

Validate your schema without generating files. Checks for errors in references, column types, and policies.

Valida seu schema sem gerar arquivos. Verifica erros em referencias, tipos de coluna e policies.

npx accessnexus push

Apply generated SQL to your database. Runs migrations, policies, triggers, RPCs, and seed (if configured) in order. Tracks applied files to avoid re-running.

Aplica o SQL gerado no banco. Roda migrations, policies, triggers, RPCs e seed (se configurado) em ordem. Rastreia arquivos aplicados para evitar re-execucao.

--url <db-url> --dry-run --target <name>
npx accessnexus seed

Populate the database with seed data. Runs automatically after push if a seed file is configured.

Popula o banco com dados iniciais. Roda automaticamente apos o push se um arquivo seed estiver configurado.

--seed <path> --url <db-url> --dry-run

DB URL fallback order: --url flag → adapterOptions.dbUrlEnv → ACCESSNEXUS_DB_URL → SUPABASE_DB_URL → DATABASE_URL

Ordem de fallback da DB URL: flag --url → adapterOptions.dbUrlEnv → ACCESSNEXUS_DB_URL → SUPABASE_DB_URL → DATABASE_URL
